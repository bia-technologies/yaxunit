# AGENTS.md — правила работы агента в этом репозитории

## Tech brief

- **Что это:** YAxUnit — фреймворк модульного тестирования для 1С:Предприятие 8.3; поставляется как расширение конфигурации (YAXUNIT).
- **Структура репозитория:**
  - `exts/yaxunit` — код расширения YAXUNIT: общие модули `ЮТ*`, обработка `ЮТЮнитТесты`;
  - `exts/smoke` — дымовые тесты;
  - `tests` — самотесты YAxUnit (расширение `tests`: модули `ОМ_*` — общие модули, `Обр_*` — обработки);
  - `fixtures/demo-configuration` — демо-конфигурация для прогонов;
  - `documentation` — документация (docusaurus, `documentation/docs/...`).
- **Язык/формат:** BSL, русские идентификаторы; исходники в EDT-формате. Платформа 8.3.27, EDT 2026.2.1.
- **Сборка/прогоны:** v8-runner (`v8project.yaml`: `format: EDT`, `workPath: build`, source-set: configuration/smoke/yaxunit/tests).
  ИБ — standalone-сервер ibsrv (`build/ibsrv`, web `:8314`, gate `1543`); тонкий клиент под X — через `xvfb-run`.
  Цели в `v8project.local.yaml`: `origin` — standalone (SSH-gate, web-клиент тестов), `filedb` — файловая база ibsrv для push (ibcmd).
  Push: остановить ibsrv → `v8-runner --infobase filedb push <SET>` → поднять ibsrv → прогоны `test ... --no-push`.
  Точечный прогон: `xvfb-run -a -s "-screen 0 1024x768x24" v8-runner test yaxunit module "<ОМ_...>" --no-push`.
- **Ключевые подсистемы для навигации:** исполнение (`ЮТИсполнительСлужебный*`), события тестирования (`ЮТСобытияСлужебный`),
  регистрация ошибок (`ЮТРегистрацияОшибок*`), фабрики описаний (`ЮТФабрика*`, `ЮТФабрикаСлужебный`),
  чтение сценариев (`ЮТЧитательСлужебный*`), отчёты jUnit/Allure (`ЮТОтчет*`).
- **Соглашения кода:** `#Область`-секции; док-комментарии к экспортным методам (кроме тестов); табуляция (не пробелы) как отступ;
  суффикс `Служебный` у внутренних модулей;
  типы ошибок и статусы исполнения — centralized в `ЮТФабрикаСлужебный.ТипыОшибок()`/`ЮТФабрика.СтатусыИсполненияТеста()`.
- **Контекст исполнения:** в директивах условной компиляции первой веткой проверяй сервер:
  `#Если Сервер` → серверный вызов, `#Иначе` → `ЮТЗапросыСлужебныйВызовСервера`; НЕ наоборот.
- **Git:** ветки `feature/{ISSUE_ID}-short-name`; коммиты `#{ISSUE_ID} message` (conventional commits);
  PR `{ISSUE_ID} / name`; ISSUE_ID обязателен — связь кода с задачами.
- **Тесты самого фреймворка пишутся в `tests`** на публичном API `ЮТест`/`ЮТТесты`; изменение количества наборов/модулей
  влияет на проверки вида `.ИмеетДлину(...)` в `ОМ_ЮТЧитательСлужебный` — обновлять осознанно.

## Жёсткие правила (никогда не…)

### 1. Согласие и скоуп

1.1. **Не трактуй молчание или точечный ответ пользователя как согласие на большее, чем он ответил.**
Если сам объявил протокол («скажи — и вношу всё разом»), только явный ответ открывает правки.
Остальное — переспрос одним компактным списком. «Не оспорил ≠ согласовал».

1.2. **Не расширяй скоуп без санкции.** Замечание ревью покрывает только само изменение;
сопутствующая миграция (перемещение данных ИБ, обновление конфигов) — отдельный вопрос.

### 2. Верификация

2.1. **Не заявляй «верифицировано», если не доказано, что проверяемый код попал в среду исполнения.**
Нет успешной загрузки (push) в текущей сессии → первая строка отчёта: «НЕ верифицировано».

2.2. **Не запускай тесты `--no-push` против ИБ с неизвестным состоянием.**
`--no-push` допустим только для ИБ, подготовленной в этой же сессии (успешный push).
Если результат прогона не различает старую и новую реализацию (одинаковые счётчики skipped/passed) —
прогон ничего не доказывает; подбирай проверяемое различие (статусы, содержимое отчёта, дубли ошибок).

2.3. **Не используй косвенные признаки (номера строк в стеках) как доказательство версии кода в ИБ,**
не сверив их со всеми кандидатами (`git show <base>:<file>`, `git show HEAD:<file>`, рабочая копия).
Совпадение с одной версией при несовпадении с другими — опровержение, а не подтверждение.

### 3. Окружение и чужие ресурсы

3.1. **Не убивай чужой процесс (по pid, порту или имени) без вопроса.**
Сначала владелец (`ps -o user=,args= -p`) и контекст; kill — только по санкции пользователя.
Пустой `list` сессий текущей переписки не означает «процесс ничей».

3.2. **Не нарушай guardrail навыка, даже если это единственный видимый путь к цели**
(ручные `1cv8`/`ibcmd`/`1cedtcli` вызовы вместо командной поверхности v8-runner и т.п.).
Штатные пути исчерпаны → остановись и запроси санкцию.

3.3. **Не изменяй конфигурацию окружения по собственной инициативе для обхода ошибки инструмента**
(`v8project.local.yaml`, провайдеры, connection-строки, пути инфраструктуры).
Обход ошибки ≠ санкция на изменение окружения. Сначала причина и вопрос.

3.4. **Не меняй инфраструктурный путь/каталог, не обновив всё ссылающееся на него**
(машинные навыки, конфиги, скрипты, известные команды запуска) —
либо явно перечислив несинхронизированное в том же ответе.

### 4. Завершённость и отчётность

4.1. **Не закрывай раунд с невыполненным собственным обязательством** («внесу и проверю прогоном»)
без явного доклада о блокере и вариантов решения.

4.2. **Вывод не может быть сильнее самого слабого звена доказательства.**
Если вход верификации недоказан — это «не выполнено», независимо от зелёных прогонов.
Оговорка внутри позитивного вывода не заменяет вердикта.

## Мягкие правила (предпочтения)

5.1. При трёх и более **разных** отказах инструмента подряд — останавливайся и докладывай:
это системная проблема окружения (пересозданный конфиг, исчезнувшие каталоги), решает владелец.

5.2. Правки файлов — инструментами edit/write. sed/python по номерам строк — крайний резерв
после отказа инструмента, с оговоркой в отчёте.

5.3. В каждом отчёте о прогрессе отделяй факты от выводов и веди явный список хвостов:
несогласованные изменения, незакрытые вопросы, невыполненные проверки — списком, не оговоркой.

5.4. Обнаружив, что команда из навыка не работает на этой машине, — зафиксируй это в отчёте
и предложи исправить навык, а не обходи молча.

## Отдельная ответственность: при неопределённости — вопрос, а не действие

Корень большинства сбоев рефлексируемой сессии: при неопределённости агент выбирал действие
(убить процесс, подправить конфиг, ручной CLI-вызов, интерпретацию молчания) вместо вопроса.
Вопрос — не замедление: в каждом эпизоде он был бы короче самовольного действия и его последствий.
