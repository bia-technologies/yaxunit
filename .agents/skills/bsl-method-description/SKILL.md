# Нестандартные правила док-комментариев (базовый формат 1С считается известным)

Базовый стандарт (секции `Параметры:` / `Возвращаемое значение:` / `Пример:`, формат `Имя - Тип - Описание`, `Массив из Тип`) не пересказывается. Ниже — только уточнения и нестандартные элементы.

## Общие правила

- Не пиши комментарий, если он не добавляет полезной информации; для простых методов с очевидным назначением описание можно опустить.
- Между секциями комментария — пустая строка.
- Описание размещается перед директивой условной компиляции, если она есть.
- В описаниях параметров вместо типа «Структура» указывай ссылку на метод-конструктор (см. ниже), для этого анализируй кодовую базу решения.
- После генерации описаний проверь все ссылки на методы — существуют ли они.
- Для экспортных методов в примере должно быть имя модуля.
- Тип общего модуля указывается в формате `CommonModule.<Имя модуля>`.
- Длина строки — не более 120 символов.

## Ссылки на методы-конструкторы («см.»)

Для параметров-структур/ТЗ и возвращаемых значений не разворачивай поля, а ссылайся:

```bsl
// Параметры:
//   ТекущаяСтрока - СтрокаТабличнойЧасти - строка табличной части документа.
//   ПараметрыЗаполненияЦен - см. ЦенообразованиеСервер.ПараметрыЗаполненияЦен
//
// Возвращаемое значение:
//   Структура - см. ЦенообразованиеСервер.ПараметрыЗаполненияЦен
//
Функция ПараметрыЗаполненияЦен() Экспорт

//   Запросы - см. Обработка.КонсольЗапросов.ТабличнаяЧасть.Запросы
//   Возвращаемое значение:
//     Массив из см. ОбновлениеИнформационнойБазы.ПараметрыОбновления
```

## Маркер «+» для списков внутри описания параметра

Если в описании параметра нужен маркированный список — используй `+` (а не `*`):

```bsl
// Параметры:
//   НесколькоНастроек - Массив - со значениями:
//     + Значение - Структура - со свойствами:
//         * Объект    - Строка
//         * Настройка - Строка
//         * Значение  - Произвольный
```
