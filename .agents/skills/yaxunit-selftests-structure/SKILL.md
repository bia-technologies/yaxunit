# Самотесты YAxUnit: структура каталога tests/

Правила конкретно этого репозитория. API тестирования (`ИсполняемыеСценарии`, регистрации, проверки, события, контекст) покрывает глобальный навык `yaxunit` — здесь только структура и конвенции каталога.

## Именование тестовых модулей

Шаблон: `[Префикс типа объекта_][Имя проверяемого объекта]{_Суффикс типа модуля}` (суффикс не обязателен, но крайне желателен).

### Префиксы типов объектов

| Тип тестируемого объекта | Префикс | Пример |
| --- | --- | --- |
| Общий модуль | `ОМ_` | ОМ_ОбщегоНазначения |
| Регистр бухгалтерии | `РБ_` | РБ_Хозрасчетный, РБ_Хозрасчетный_НЗ |
| Регистр накопления | `РН_` | РН_ОстаткиНаСкладах, РН_ОстаткиНаСкладах_ММ |
| Регистр расчета | `РР_` | РР_Зарплата, РР_Зарплата_НЗ |
| Регистр сведений | `РС_` | РС_АдресныйКлассификатор |
| Бизнес процесс | `БП_` | БП_Согласование |
| Справочник | `Спр_` | Спр_Пользователи, Спр_Пользователи_МО |
| План счетов | `ПС_` | ПС_Хозрасчетный |
| План видов расчета | `ПВР_` | ПВР_Зарплатный |
| План видов характеристик | `ПВХ_` | ПВХ_Субконто, ПВХ_Субконто_ММ |
| Документ | `Док_` | Док_ПКО |
| Перечисление | `Пер_` | Пер_СтатусСогласования |
| План обмена | `ПО_` | ПО_РИБ, ПО_РИБ_ММ |
| Задача | `Зад_` | Зад_Задача |
| Обработка | `Обр_` | Обр_ЗакрытиеМесяца, Обр_ЗакрытиеМесяца_МО |
| Отчет | `Отч_` | Отч_УниверсальныйОтчет |

### Суффиксы типов модулей

| Тип тестируемого модуля | Суффикс | Пример |
| --- | --- | --- |
| Общий модуль | `<Без суффикса>` | ОМ_ОбщегоНазначения |
| Модуль объекта | `_МО` | Спр_Пользователи_МО, Обр_ЗакрытиеМесяца_МО |
| Модуль менеджера | `_ММ` | ПВХ_Субконто_ММ, ПО_РИБ_ММ |
| Модуль набора записей | `_НЗ` | РБ_Хозрасчетный_НЗ, РР_Зарплата_НЗ |

Пример: для документа `ПоступлениеДенег` — `Док_ПоступлениеДенег` в `tests/src/CommonModules/Док_ПоступлениеДенег/Module.bsl`.

## Создание нового тестового модуля

Тесты — общие модули в `tests/src/CommonModules/`. Для нового модуля создай файлы, если отсутствуют:

1. Каталог `tests/src/CommonModules/[Имя модуля]`
2. Описание `tests/src/CommonModules/[Имя модуля]/[Имя модуля].mdo`:
   ```xml
   <?xml version="1.0" encoding="UTF-8"?>
   <mdclass:CommonModule xmlns:mdclass="http://g5.1c.ru/v8/dt/metadata/mdclass" uuid="{uuidgen}">
   <name>[Имя модуля]</name>
   <clientManagedApplication>true</clientManagedApplication>
   <server>true</server>
   <clientOrdinaryApplication>true</clientOrdinaryApplication>
   </mdclass:CommonModule>
   ```
   - **Не обновляй существующий .mdo** — только создавай отсутствующий.
   - Для модулей объектов и менеджеров (`_МО`, `_ММ`): `<server>true</server>`, остальные флаги false.
   - Для общих (`ОМ_`): флаги `clientManagedApplication`, `server`, `clientOrdinaryApplication` — в соответствии с настройками проверяемого модуля.
3. Модуль `tests/src/CommonModules/[Имя модуля]/Module.bsl`
4. **Обязательно зарегистрируй модуль в `tests/src/Configuration/Configuration.mdo`** — без этого EDT его не увидит.

## Конвенции тестов

- **Имя тестовой процедуры = имени проверяемого метода**, без префиксов/суффиксов «Тест»/«Проверить».
- При регистрации используй fluent-интерфейс (`ЮТТесты.ДобавитьТест(...).СПараметрами(...)`).
- Описание тестов в формате markdown создавать не нужно.
- Новые модули/наборы влияют на проверки вида `.ИмеетДлину(...)` в `ОМ_ЮТЧитательСлужебный` — обновляй счётчики осознанно.
